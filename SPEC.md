# ТЗ: демо-страница киоска Digital Human (Orange Slovensko)

Спека для реализации. Читать целиком до начала работы.

---

## 1. Что это

Одностраничное веб-приложение, имитирующее экран напольного киоска в магазине.
Показывается Orange Slovensko на презентации предложения (окно 6–14.08.2026).
Внутри — два варианта «головы» аватара, каждый в своём iframe:

| Вариант | Движок | Пол аватара | Источник |
|---|---|---|---|
| A | UE5 / MetaHuman (наша сборка) | женский | URL из конфига (pixel streaming) |
| B | anam.ai | мужской | embed-URL из конфига |

Страница вокруг iframe — наша: весь интерфейс, состояния, ввод номера, 3D-устройства,
обратная связь. Аватар отвечает только за лицо и голос.

## 2. Жёсткие ограничения

**Конфиденциальность.** Проект под NDA, штраф за нарушение — 33 000 EUR.
- Страница **не публикуется в открытом доступе**. Локальный запуск или статический
  хостинг с basic-auth.
- `<meta name="robots" content="noindex, nofollow">` обязательно.
- Никаких аналитик, трекеров, внешних CDN со статистикой, Sentry и подобного.
- В названии файлов, заголовке страницы и коде — никаких упоминаний тендера.
  Title: `Digital Assistant Demo`.

**Раскрытие AI.** На экране должно быть постоянно видно, что собеседник —
AI-аватар, а не человек. Требование и anam.ai, и AI Act (ст. 9 договора с Orange).
Текст: `Rozprávate sa s digitálnym asistentom (AI)`.

**Язык интерфейса — только словацкий.** Все строки. Английских надписей быть не должно.

## 3. Технические требования

**Разрешение.** Логический холст ровно **1080 × 1920 px** (портрет).

Масштабирование под окно браузера:

```
scale = min(window.innerWidth / 1080, window.innerHeight / 1920)
```

Холст центрируется через `transform: scale(...)` + `transform-origin: center`,
пространство вокруг — сплошной чёрный. Никакого адаптива внутри холста:
вёрстка фиксированная под 1080×1920, координаты в px.

**Стек.** Без сборки. Один `index.html` + `styles.css` + `app.js` + `config.js`.
Открывается двойным кликом или через `python3 -m http.server`.
Фреймворки не нужны. Из внешнего допускается только `<model-viewer>` для 3D.

**iframe.**
```html
<iframe src="..." allow="microphone; autoplay; clipboard-write"
        allowfullscreen frameborder="0"></iframe>
```
Камера **не запрашивается никогда** — в решении её нет, и это заявлено Orange письменно.

**Конфиг** — отдельный `config.js`, чтобы менять URL без правки кода:

```js
const CONFIG = {
  avatarA: { engine: 'metahuman', gender: 'female', url: 'ЗАПОЛНИТЬ' },
  avatarB: { engine: 'anam',      gender: 'male',   url: 'ЗАПОЛНИТЬ' },
  idleTimeoutSec: 45,
  phonePrefix: '+421',
  devices: [ /* см. раздел 6 */ ],
  addresses: [ /* см. раздел 7 */ ]
};
```

## 4. Состояния экрана

Конечный автомат, переходы явные:

```
IDLE ──(касание / обнаружен голос)──► GENDER_SELECT ──► CONVERSATION
                                                          │
                    ┌─────────────────────────────────────┤
                    ▼                 ▼                   ▼
              DEVICE_3D      COVERAGE_CHECK          LEAD_CAPTURE
                    │                 │                   │
                    └────────► CONVERSATION ◄─────────────┘
                                      │
                                      ▼
                              FEEDBACK ──► IDLE
```

Возврат в `IDLE` — автоматически через `idleTimeoutSec` бездействия из любого состояния.

### 4.1 IDLE (режим ожидания)

Требование Orange: в простое аватар работает **только визуально, без звука**.

- Аватар в iframe в спокойной анимации, **звук выключен полностью**
- Поверх — сменяющиеся приглашающие сообщения на словацком, крупно:
  `Opýtajte sa ma na čokoľvek o službách Orange`
  `Skontrolujem dostupnosť služieb na Vašej adrese`
  `Ukážem Vám zariadenia z ponuky`
- Крупная кнопка снизу: `Dotknite sa obrazovky`
- Любое касание → `GENDER_SELECT`

### 4.2 GENDER_SELECT (выбор аватара)

Требование Orange: выбор внешности вручную клиентом, **только пол**.
Никакой этничности, возраста, одежды — это исключено заказчиком явно.

- Заголовок: `S kým sa chcete rozprávať?`
- Две крупные карточки: `Žena` / `Muž`
- Выбор `Žena` → грузится iframe варианта A, `Muž` → вариант B
- Мелким шрифтом снизу: `Vzhľad asistenta si môžete kedykoľvek zmeniť`

> Примечание для реализации: в демо выбор пола фактически переключает движок.
> Это допустимая условность демо, но в коде **не смешивать** понятия:
> `gender` — пользовательское, `engine` — техническое. Связь задаётся в конфиге.

### 4.3 CONVERSATION (основной экран)

Компоновка сверху вниз в пределах 1080×1920:

| Зона | Высота ≈ | Содержимое |
|---|---|---|
| Шапка | 120 px | Логотип-плейсхолдер, плашка `Rozprávate sa s digitálnym asistentom (AI)` |
| Аватар | 1000 px | iframe, вписан по ширине |
| Субтитры | 260 px | Текст текущей реплики аватара, крупно, 2–3 строки |
| Быстрые действия | 320 px | Четыре кнопки, см. ниже |
| Подвал | 220 px | Кнопка `Chcem hovoriť s predajcom`, индикатор микрофона |

Четыре кнопки быстрых действий (сетка 2×2):

1. `Mobilné služby`
2. `Internet a TV`
3. `Ukáž mi zariadenia` → `DEVICE_3D`
4. `Dostupnosť na mojej adrese` → `COVERAGE_CHECK`

Индикатор микрофона — визуальный уровень звука, чтобы на демо было видно,
что аватар слышит. Работает от Web Audio API, локально, **без записи**.

### 4.4 Переход к продавцу

Экран-оверлей: `Zavolám Vám predajcu` + анимация + кнопка `Späť k asistentovi`.
Это ключевой сценарий для Orange — аватар честно признаёт предел компетенции.
Должен вызываться и вручную (кнопка), и программно (dev-контрол).

## 5. LEAD_CAPTURE — ввод номера телефона

Самая ответственная часть по GDPR. Реализовать ровно так, как заявлено Orange.

Порядок экранов:

1. **Предложение.** `Chcete, aby sa Vám ozval náš predajca?` → `Áno` / `Nie, ďakujem`
2. **Информация о приватности — до ввода номера.** Отдельный экран, не мелкий текст:

   > Vaše telefónne číslo odovzdáme predajcovi Orange, aby Vás mohol kontaktovať.
   > Neuchovávame ho v tomto zariadení ani v cloude.
   > Nezbierame meno, priezvisko ani žiadne iné údaje. Zariadenie nemá kameru.

   Чекбокс: `Rozumiem a súhlasím` — **неотмеченный по умолчанию**.
   Кнопка `Pokračovať` неактивна, пока чекбокс не отмечен.

3. **Ввод номера.** Экранная цифровая клавиатура — физической клавиатуры у киоска нет.
   - Префикс `+421` зафиксирован слева, не редактируется
   - Клавиши 0–9, `Zmazať`, `Odoslať`
   - Клавиши крупные, не меньше 140×140 px — палец, не мышь
   - Валидация: 9 цифр после префикса, иначе `Odoslať` неактивна
4. **Подтверждение.** `Ďakujeme, predajca sa Vám ozve.` → авто-возврат через 5 сек

**Важно:** в демо номер **никуда не отправляется**. В консоль писать только
`lead created` без самого номера — так же, как заявлено Orange в дотазнике
(«maskované v logoch»). Заглушку интеграции с CB24 оформить как отдельную
функцию `submitLead(phone)` с комментарием, что в проде туда идёт
зашифрованный API-ключ и запись в папку `Leady z avatara`.

## 6. DEVICE_3D — 3D-визуализация устройств

Что именно визуализируем: **устройства из каталога orange.sk** — смартфоны,
планшеты, роутеры. Orange 3D-моделей не даёт, делаем сами; в коммерческом
предложении заложено до 10 устройств. Для демо достаточно 2–3.

Это наше главное отличие от чистых SaaS-аватаров — показать обязательно.

Реализация: `<model-viewer>` с файлами `.glb`.

```html
<model-viewer src="models/device1.glb" camera-controls auto-rotate
              shadow-intensity="1" exposure="1"
              interaction-prompt="none"></model-viewer>
```

Экран:
- Горизонтальная лента карточек устройств (название + цена-плейсхолдер)
- По тапу — крупный `<model-viewer>` на ~60 % высоты холста
- Вращение пальцем, кнопка `Otočiť` для автоповорота
- Аватар сжимается в верхнюю четверть и продолжает говорить
- Кнопки: `Späť`, `Chcem o tomto vedieť viac` → `LEAD_CAPTURE`

Конфиг:
```js
devices: [
  { id: 'dev1', name: 'ЗАПОЛНИТЬ', model: 'models/dev1.glb', price: '—' },
]
```

Если `.glb` ещё нет — заглушка: вращающийся примитив с подписью
`3D model – placeholder`. Верстку это блокировать не должно.

## 7. COVERAGE_CHECK — доступность услуг по адресу

Требование из ТЗ Orange: проверка доступности услуг Orange по адресу.

- Поле адреса + экранная клавиатура (буквы, словацкая раскладка с диакритикой)
- Автодополнение из захардкоженного списка в конфиге
- Результат: карточка `Optika – dostupná` / `4G/5G – dostupné` / `Optika – nedostupná`
- Кнопка `Chcem to objednať` → `LEAD_CAPTURE`

Данные мокаем. Три-четыре адреса Братиславы в конфиге, один из них — заведомо
без оптики, чтобы показать честный отрицательный ответ.

```js
addresses: [
  { q: 'Pribinova 8, Bratislava', optika: true,  mobil: true },
  { q: 'Metodova 8, Bratislava',  optika: true,  mobil: true },
  { q: 'ЗАПОЛНИТЬ',              optika: false, mobil: true },
]
```

## 8. FEEDBACK — оценка

Требование ТЗ: обратная связь палец вверх / палец вниз.

- Появляется при завершении сессии и по кнопке `Ukončiť`
- `Bol som Vám nápomocný?` + две крупные иконки
- После выбора: `Ďakujeme` → `IDLE`
- Счётчик в `localStorage`, показывается только в dev-панели

## 9. Dev-панель и контроль соединения

### 9.1 Dev-панель (скрытая)

Нужна проджект-менеджеру на демо. Открывается **тройным тапом в правый верхний
угол** — не кнопкой, чтобы клиент не наткнулся случайно.

Содержит:

- Переключатель движка: `MetaHuman A` / `anam B` — принудительно, независимо от пола
- **Переключатель акцентного цвета: `Oranžová` / `Čierna`** — меняет всю тему
  интерфейса, см. раздел 10. Выбор сохраняется в `localStorage`
- `Simulovať výpadok internetu` — принудительно включает экран потери связи
- `Simulovať otázku mimo kompetencie` — принудительный переход к продавцу
- Сброс в `IDLE`
- Счётчики: сессии, лиды, палец вверх/вниз
- Индикатор FPS
- Текущий статус соединения: `online` / `offline` + время последней успешной проверки

### 9.2 Контроль соединения с интернетом

Реальная логика, не только симуляция. Работает всегда, во всех состояниях.

**Определение потери связи** — три источника, срабатывает любой:

1. События `online` / `offline` браузера. Быстро, но ненадёжно: `navigator.onLine`
   показывает наличие сети, а не интернета. Использовать как первый сигнал,
   но не как единственный.
2. **Heartbeat.** Каждые 5 секунд `fetch()` с `cache: 'no-store'` и таймаутом
   3 секунды на лёгкий заведомо доступный ресурс (например, favicon домена,
   на котором крутится iframe). Два подряд неудачных запроса → считаем офлайн.
   Один удачный → снова онлайн.
3. **Отказ iframe.** Обработчик `onerror` и таймаут загрузки: если iframe
   не выдал событие `load` за 15 секунд — считаем недоступным.

Дребезг гасить: переход в офлайн — после двух неудач подряд, возврат в онлайн —
после одной удачи. Иначе на нестабильном Wi-Fi экран будет мигать.

**Что показывать.** Поверх области аватара — оверлей на всю зону iframe,
непрозрачный, iframe под ним не выгружается (чтобы восстановился сам).

Текст по умолчанию:

> **Žiadne pripojenie k internetu**
> Skontrolujte pripojenie k internetu.

Плюс мелким шрифтом снизу: `Pokus o obnovenie spojenia…` и крутящийся индикатор.

Восстановление связи → оверлей исчезает сам, iframe перезагружается один раз,
состояние экрана сохраняется. Пользователя никуда не выбрасывает.

**Второй вариант текста для реального магазина.** В конфиге флаг:

```js
offlineMode: 'technical'  // 'technical' | 'customer'
```

- `technical` — текст выше. Для демо и для тестовой недели: сразу видно, что случилось
- `customer` — нейтральный текст для реального магазина, где посетитель всё равно
  ничего не починит:
  `Momentálne prebieha aktualizácia. Obráťte sa prosím na predajcu.`

На демо ставим `technical` — при симуляции обрыва Orange должен видеть,
что система понимает своё состояние, а не просто зависает.

**Чего не делать при потере связи:** не показывать браузерные ошибки, не выводить
стек, не белый экран, не бесконечный спиннер без текста. Никаких английских надписей.

## 10. Оформление

- Фон тёмный, аватар — светлое пятно в центре внимания
- Шрифт крупный: минимальный кегль текста 32 px, заголовки от 64 px.
  Экран смотрят стоя, с расстояния метра-полутора
- Кликабельные зоны не меньше 120×120 px
- Никакой анимации ради анимации: переходы 200–300 ms, без параллаксов

**Акцентный цвет — переключаемый.** Все цвета задаются CSS-переменными,
смена темы меняет одну переменную, а не двадцать мест в стилях:

```css
:root {
  --accent: #FF7900;        /* оранжевая тема */
  --accent-contrast: #FFF;  /* текст на акценте */
}
[data-theme="black"] {
  --accent: #000000;        /* чёрная тема */
  --accent-contrast: #FFF;
}
```

Переключается из dev-панели (раздел 9.1), состояние в `localStorage`.
Никаких захардкоженных `#FF7900` в коде — только `var(--accent)`.

**Важно для чёрной темы:** фон интерфейса тёмный, поэтому чёрный акцент
на тёмном фоне сольётся. В чёрной теме кнопки и активные элементы делать
светлыми — белая заливка с чёрным текстом, либо чёрная заливка с белой обводкой.
Проверить, что все кнопки читаемы в обеих темах, это входит в приёмку.

**Логотип Orange.** В демо использовать плейсхолдер или их логотип — решает Алексей
перед показом. По ст. 4.5 договора использование логотипа требует письменного
согласия; для показа самому Orange это нормально, но в коде вынести в конфиг
одной строкой, чтобы можно было убрать.

## 11. Чего не делать

- Не запрашивать камеру
- Не сохранять номер телефона никуда, включая `localStorage`
- Не подключать внешние аналитики и шрифтовые CDN с трекингом
- Не делать адаптив под мобильные — только масштабирование холста
- Не добавлять экранов, которых нет в этой спеке

- [ ] 3D-устройство вращается пальцем
- [ ] Проверка адреса даёт и положительный, и отрицательный ответ
- [ ] Dev-панель открывается тройным тапом и закрывается

- [ ] На нестабильном соединении экран не мигает (дребезг погашен)
- [ ] Ни одной английской надписи в интерфейсе
