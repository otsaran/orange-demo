# Digital Assistant Demo

Одностраничный киоск-демо (портрет 1080 × 1920) с аватаром в iframe. Без сборки,
без фреймворков, без внешних трекеров. Страница не для публичного размещения:
локальный запуск или статический хостинг с basic-auth.

Этот файл — точка сохранения проекта: состояние, принятые решения и что осталось.

## Запуск

```bash
python3 -m http.server 8123
```

Открыть `http://localhost:8123`. Двойной клик по `index.html` тоже работает, но при
`file://` браузер блокирует загрузку iframe с 3D-стойками и не идёт heartbeat —
остальной интерфейс функционален. Для показа — F11.

Холст масштабируется под окно: `scale = min(w/1080, h/1920)`, поля чёрные,
вёрстка внутри фиксированная в px.

выбора аватара. Весь остальной интерфейс работает без интернета.

## Экраны и переходы

```
IDLE ──(касание)──► GENDER_SELECT ──► CONVERSATION
                                          │
        ┌──────────────┬──────────────────┼────────────────┐
        ▼              ▼                  ▼                ▼
      PLANS        DEVICE_3D        COVERAGE_CHECK       SELLER
        │              │                  │                │
        └──► COVERAGE_CHECK / LEAD_CAPTURE ┴────► CONVERSATION
                                          │
                                          ▼
                                    FEEDBACK ──► IDLE
```

Из любого состояния сессии бездействие `idleTimeoutSec` (45 с) уводит в `FEEDBACK`,
оттуда `feedbackTimeoutSec` (15 с) — в `IDLE`.

**Четыре плитки в CONVERSATION** (ключ = `data-quick`):

| Плитка | Куда ведёт |
|---|---|
| `mobile` — Paušály | карусель `plans.mobile` → `LEAD_CAPTURE` |
| `phones` — Telefóny | `DEVICE_3D` (витрина стоек) |
| `tv` — Televízia | карусель `plans.tv` → `COVERAGE_CHECK` |
| `internet` — Internet | карусель `plans.internet` → `COVERAGE_CHECK` |

Маршруты: если ключ плитки есть в `CONFIG.plans` — открывается карусель, иначе
берётся `QUICK_TARGET` в `app.js`. Новый раздел = блок в конфиге + плитка в HTML.

**PLANS** — один экран на все разделы. Заголовок, надпись на кнопке и её маршрут
(`next`) приходят из конфига. Карточка: название, крупный акцентный показатель,
подстрока, описание, старая/новая цена, срок, «Vybrať», список бенефитов.
Прокрутка пальцем со snap, перетаскивание мышью (для показа с ноутбука),
полоса-индикатор вместо системного скроллбара.

## Заставка IDLE

Вместо живого аватара в простое крутится зацикленная подборка, чтобы движок
аватара не работал вхолостую:

```
bg.webp 5 с → video_m 20 с → bg.webp 5 с → video_w 20 с → по кругу
```

Видео без звука, внутри 20-секундного окна повторяются сами. Цикл живёт только
в `IDLE`: при уходе на другой экран таймер гасится и видео ставятся на паузу.
Правится в `STUB_CYCLE` в `app.js`.

## Выбор аватара

Плитки квадратные, с зацикленными видео `orange_w.webm` / `orange_m.webm` во всю
площадь; подписи «Žena» / «Muž» вынесены под плитки. Выбранная отмечается
оранжевой рамкой с внутренним кольцом и оранжевой подписью — заливка не годится,
её перекрывает видео. У кнопок `aria-label`, потому что подпись снаружи.

Видео без звука, играют только на этом экране: при уходе ставятся на паузу, при
возврате перематываются на начало (`setGenderVideos` в `app.js`). Прежние
`orange_w.webp` / `orange_m.webp` остались как `poster` — они видны, пока видео
не декодировалось, иначе на их месте была бы чёрная плашка.

## Витрина стоек (DEVICE_3D)

Три готовые страницы `totem-1/2/3.html` вставляются в один iframe, у которого при
выборе карточки меняется `src`. Напрямую в разметку их вставить нельзя: у каждой
свои скрипты и совпадающие `id`. Один iframe вместо трёх — один живой WebGL-контекст.

Внутри страниц вёрстка переделана под киоск: модель во всю ширину (968 × 778),
кнопки `Rozmery` / `Pôvodný pohľad` / `Fotografia` перенесены из вертикальной
колонки справа под модель и приведены к форме киоскового `.btn-soft` (32 px,
высота 110, активная — оранжевая с чёрным текстом). Собственная карточка страницы
(фон, рамка, скругление, паддинг) убрана, фон `body` прозрачный — рамку даёт
киоск. Свой медиазапрос `max-width:640px` внутри оставлен: он не срабатывает
(iframe всегда 968 px), но нужен, если открывать файл напрямую.

Прежний пайплайн на `model-viewer` + `.glb` удалён целиком вместе с CSS-заглушкой
вращающегося куба.

## Аватар на внутренних экранах

| Экран | Зона аватара |
|---|---|
| `IDLE` | 1080 × 1180 |
| `CONVERSATION` | 1080 × 920 |
| `DEVICE_3D` | 800 × 450 (16:9) |
| `PLANS` | 800 × 450 (16:9) |
| `COVERAGE_CHECK` | нет аватара |

Полоса на внутренних экранах держит 16:9 и стоит по центру, а не растягивается на
всю ширину. Размер 800 × 450 упирается в карусель тарифов: карточкам нужно 1006 px
из 1010, поэтому больший аватар пришлось бы вычитать прямо из них. 800 × 450 —
потолок при нетронутых карточках, и он же взят на витрине стоек ради единообразия.

На `COVERAGE_CHECK` аватара нет вовсе: там будет обычная форма ввода адреса.
Следствие — оверлей обрыва связи на этом экране не показывается, он живёт внутри
слоя аватара (так же ведёт себя `GENDER_SELECT`).

## Виджет anam.ai

Аватар — веб-компонент `<anam-agent>` (`vendor/anam-agent.js`, версия 0.5.0),
а не iframe. Элемент создаётся в `#avatarWidget` после выбора пола и при уходе
в `IDLE` удаляется целиком — это единственная надёжная гарантия тишины в простое.
Скрипт виджета грузится лениво, при первом создании: в `IDLE` наружу не уходит
ни один запрос. Если файла во `vendor/` нет, подхватывается `scriptFallback` с CDN.

Ветка по `engine` в `loadAvatar`: `anam` + непустой `agentId` → виджет; иначе
непустой `url` → прежний iframe (pixel streaming); иначе — заставка-заглушка.
Женский аватар сейчас в третьей ветке, до появления его `agent-id`.

Три поправки к виджету, каждая по своей причине:

- **Автостарт.** Виджет ждёт нажатия собственной кнопки. На киоске её нажимаем
  сами (`.anam-cta-pill` в открытом shadow DOM) — выбор пола и есть то
  пользовательское действие, после которого браузер разрешает спросить микрофон.
- **Размер.** Виджет держит 16:9 и оставил бы в зоне аватара пустую полосу.
  В shadow DOM дописан стиль: `.anam-widget/.anam-sheet/.anam-video-region`
  тянутся на всю зону, кадрирование делает сам виджет (`object-fit: cover`).
- **Слои.** Внутри у виджета `z-index: 9999`, поэтому он перекрывал оверлей
  обрыва связи. `#avatarWidget` получил свой `z-index`, и внутренние слои
  остались заперты в нём.

Собственный хром виджета выключен (`ui-transcript`, `ui-captions`,
`ui-mute-button`, `ui-text-input` = `false`): индикатор микрофона, титры и
кнопки у киоска свои. Водяной знак «Anam» остаётся — он снимается на стороне
сервиса, не в разметке.

**События.** `session-started` снимает оверлей обрыва, `error` его показывает
(вместе с таймаутом `iframeLoadTimeoutMs`), `message-received` с ролью не-`user`
уходит в титры. Heartbeat у виджета своей URL нет, поэтому пингуется
`anam.probeUrl` (`api.anam.ai`).

**Инструменты аватара** (client tools). Таблица `AVATAR_TOOLS` в `app.js` — весь
список того, что аватар может сделать с экраном; названия должны совпасть с
инструментами персоны в кабинете anam.ai:

| Инструмент | Аргументы | Действие |
|---|---|---|
| `show_section` | `section`: `mobile` \| `phones` \| `tv` \| `internet` | та же плитка, что и пальцем |
| `show_devices` | `model`: `totem1…3` | витрина стоек с нужной моделью |
| `check_coverage` | — | проверка адреса |
| `capture_lead` | — | форма для перезвона |
| `call_seller` | — | экран продавца |
| `end_conversation` | — | оценка и возврат в `IDLE` |

Серверные (webhook) вызовы игнорируются — их выполняет движок anam.ai сам.
Неизвестное имя инструмента только пишется в консоль.

Инструменты заводятся не руками, а скриптом `scripts/anam-tools.mjs` — в нём
те же шесть определений с описаниями и JSON-схемами:

```bash
ANAM_API_KEY=… node scripts/anam-tools.mjs --dry-run   # показать план
ANAM_API_KEY=… node scripts/anam-tools.mjs             # применить
```

Заведены и привязаны к мужской персоне 2026-08-04; проверено на живой сессии:
на «Použi nástroj show_section so sekciou mobile» пришёл
`tool-call-started {section: 'mobile'}` и киоск открыл карусель тарифов.
Публиковать персону заново для этого не нужно — виджет берёт актуальный
конфиг, не снимок `publishedAt`.

Скрипт идемпотентный: инструмент с таким же именем не дублируется, у него
обновляются описание и схема. `toolIds` персоны **дополняются**, а не
переписываются — системные `end_call`, `change_language`, `skip_turn` остаются
на месте. Ключ берётся из окружения и никуда не пишется; `.env.local` в
`.gitignore`. Персона задаётся через `ANAM_PERSONA_ID`, по умолчанию — мужская.

**Промпт персоны** — `scripts/persona-prompt.md`, заливается вторым скриптом:

```bash
ANAM_API_KEY=… node scripts/anam-persona.mjs --dry-run
ANAM_API_KEY=… node scripts/anam-persona.mjs
```

Он же ставит `languageCode: sk` и приветствие. Что заложено в текст: аватар —
цифровой презентёр Humion, оператор не называется ни разу (NDA), словацкий по
умолчанию с переходом на английский по просьбе (через системный
`change_language`), цены голосом не зачитываются — они на экране, выдумывать
числа запрещено, при сомнении — `call_seller`. Инструмент вызывается **до**
рассказа, чтобы посетитель видел то, о чём речь. Персональные данные не
спрашиваются: номер вводит сам посетитель после `capture_lead`.

Строка `LINES.hello` в `app.js` тоже без названия оператора — её видно те
секунды, пока не заговорил аватар.

**Обратное направление — киоск говорит аватару.** У виджета нет публичного
`talk()`, поэтому вопрос уходит через его же поле ввода — оно включено
(`ui-text-input: 'true'`), но скрыто стилем: на киоске не печатают, поле нужно
только как канал. Выключается одним флагом `anam.textBridge`.

| Что нажали | Что уходит аватару |
|---|---|
| плитка раздела | `anam.ask[ключ]` — «Povedz mi o paušáloch» и т. д. |
| «Vybrať» на карточке | шаблон `anam.askPlan` с фактами карточки |

Факты в вопрос подставляются из `config.js` (название, крупный показатель,
описание) — модель их не выдумывает, а цены ей прямо запрещено зачитывать: они
у посетителя на экране.

Важная тонкость: виджет на preact, и состояние поля обновляется в следующем
такте — отправлять надо через `setTimeout`, иначе уходит пустая строка и
ошибки не видно. Если понадобится детерминированная речь по кнопке (зачитать
цену слово в слово), это повод перейти с виджета на JS SDK, где `talk()` есть.

## Оформление

Токены из дизайн-системы Orange (тёмный режим), сверены по Boosted 5.3 — их
собственной реализации гайда. Размеры и кегли не оттуда: они киоскные, под
просмотр стоя с полутора метров (текст от 32 px, тап-зоны от 120 px).

| | Значение | Откуда |
|---|---|---|
| Оранжевый | `#FF7900` | акцент тёмного режима (на белом у них `#F16E00`) |
| Текст на оранжевом | `#000` | правило контраста Orange |
| Фон / панель / линия | `#141414` / `#333` / `#666` | серые тона системы |
| Радиусы | 12 / 14 / 16 px | их 6–16 px, масштабировано под кнопку 130 px |
| Рамки | 2 px | `--bs-border-width: 0.125rem` |
| Нажатие | инверсия цветов | `.btn-primary:active` → чёрный фон, белая рамка |
| Неактивное | сплошной серый `#666` | у них `opacity: 1`, не прозрачность |
| Шрифт | Helvetica Neue 400/500/700 | `HelvNeueOrange` в их стеке |
| Фокус | 3 px кольцо + 2 px внутренний лем | правило доступности Orange |

Ни градиентов, ни теней, ни свечения — система плоская. Веса только 400/500/700:
`font-synthesis: none`, промежуточных начертаний в поставке нет.

**Чёрная тема** (переключатель в dev-панели, требование ТЗ): акцент `#000` на
тёмном фоне сливается, поэтому активные элементы белые с чёрным текстом — это
совпадает с их же `.btn-secondary` в тёмном режиме. Выбор состояния, который в
оранжевой теме показан обводкой, в чёрной дополнительно подсвечивается плашкой.

**Логотип** рисуется кодом: фирменный квадрат 96 × 96, слово в левом нижнем углу,
™ приподнято. Пропорции сняты с оригинала (слово ≈ 78 % ширины, поля 7–8 %).
В чёрной теме — монохромная инверсия.

**Плашка «Rozprávate sa s digitálnym asistentom (AI)»** — только текст с точкой,
без рамки и подложки; выровнена по правому отступу шапки.

## Приватность и NDA

- Камера не запрашивается нигде и никогда.
- Микрофон — только уровень громкости через Web Audio API, без записи и передачи.
- Номер телефона не сохраняется ни в `localStorage`, ни где-либо ещё; после
  отправки переменная очищается. В консоль пишется только `lead created`.
- `submitLead(phone)` в `app.js` — заглушка интеграции; в проде туда идёт
  зашифрованный ключ и запись в папку `Leady z avatara` (CB24).
- В `localStorage` только тема и обезличенные счётчики сессий и оценок.
- `noindex, nofollow` в head.
- Единственный внешний обмен — сессия anam.ai (голос посетителя и видеопоток
  аватара) и только между выбором аватара и возвратом в `IDLE`. В простое
  наружу не уходит ничего: элемент виджета удалён, скрипт лежит локально.

**Замены ради конфиденциальности** (каждая — одна строка в конфиге):
слово в логотипе → `logo`; названия партнёрских сервисов в бенефитах →
нейтральные («Prémiový filmový balík», «TV balík»).

## Контроль соединения

Три независимых источника: события `online`/`offline`, heartbeat каждые 5 с
(`no-store`, таймаут 3 с), таймаут загрузки аватара 15 с. Офлайн — после двух
неудач подряд, онлайн — после одной удачи (дребезг погашен).

**Живая сессия аватара сильнее пробы.** Пока идёт WebRTC-поток (пришло
`session-started` и не было `session-ended`/`error`), оверлей не показывается,
даже если heartbeat не отвечает: работающий стрим — доказательство связи
надёжнее, чем opaque-fetch в `api.anam.ai`, который может резать расширение
или заголовок CORP. Без сессии (простой, iframe, заглушка) логика прежняя.
В dev-панели причина теперь разделена: строка **Relácia** (идёт / последняя
ошибка виджета) и строка **Sonda** (heartbeat и время последнего ответа). Оверлей накрывает
только зону аватара, iframe под ним не выгружается и восстанавливается сам.
Текст переключается флагом `offlineMode`.

Heartbeat активен, когда известен внешний URL (`heartbeat.url` или адрес
аватара). Без него работают события браузера и таймаут iframe.

В узкой полосе 16:9 карточка оверлея идёт на ступень мельче (заголовок 38,
подпись 24, иконка 56), иначе текст не помещается и обрезается.

## Dev-панель

Тройной тап в правый верхний угол холста (скрытая зона 190 × 190, интервал 1,6 с).
Панель полупрозрачная со стеклом (`backdrop-filter`), лежит поверх сцены.

- переключатель чёрной темы (тумблер, кружок красится в текущий акцент);
- «Simulovať výpadok internetu» — симуляция обрыва связи;
- «Reset do IDLE»;
- счётчики: состояние, пол, аватар, сессия аватара, соединение, heartbeat,
  сессии, лиды, оценки, FPS.

   `Ukáž mi zariadenia`, `Dostupnosť na mojej adrese`. Сейчас: `Paušály`,
   `Telefóny`, `Televízia`, `Internet` — по решению заказчика, чтобы совпадать
   с разделами сайта. Проверка адреса теперь внутри «Internet» и «Televízia».
2. **§10, пример CSS.** В ТЗ `--accent-contrast: #FFF` (белый текст на оранжевом).
   Поставлен `#000`: у Orange жёсткое правило контраста — текст на оранжевом
   чёрный. Переменная и её смысл сохранены.
3. **§4.3, высоты зон.** Подвал увеличен за счёт зоны аватара (920 вместо 1000),
   иначе кнопка продавца и индикатор микрофона не помещались с тап-зонами 120 px.
4. **IDLE.** Аватар не просто без звука — он не загружается вовсе. Ни чужой
   iframe, ни виджет нельзя заглушить снаружи, а требование «в простое без
   звука» жёсткое. Загружается после выбора аватара.
5. **Карусели тарифов** — новый экран, которого в ТЗ нет (§11 «не добавлять
   экранов»). Добавлен по прямому запросу заказчика.
6. **Витрина стоек вместо витрины устройств.** По ТЗ там телефоны и роутеры в
   `.glb`; по решению заказчика показываются собственные киоски трёх размеров
   готовыми Three.js-страницами.

## Что осталось

- [ ] **Домен в кабинете anam.ai.** Персона отдаёт `Origin not allowed`, пока
      адрес киоска не внесён в список разрешённых. Для проверки нужен
      `http://localhost:8123`, для показа — тот адрес, с которого пойдёт демо.
- [ ] `avatarA.agentId` — женский виджет (сейчас пусто → показывается заставка)
- [ ] Промпт персоны сверить перед показом: он писан без прайса и без названия
      оператора, но фактура (размеры стоек, состав разделов) должна совпасть
      с `config.js`, если карусели поменяются
- [ ] `devices[]` — цены стоек, если нужны (сейчас поля цены нет вовсе)
- [ ] `addresses[]` — третий адрес заведомо без оптики (сейчас плейсхолдер
      `Vajnorská 100`)
- [ ] `plans.*` — сверить цены и тексты с актуальной ценовой на дату показа
- [ ] Решение по логотипу: оставить рисованный квадрат, подставить файл через
      `logo.src` или убрать `logo.show = false`
- [ ] **Иконки.** Сейчас свои контурные. Фирменный набор Solaris — плоский,
      заливкой, без обводок; скачивается с oran.ge/icons, лицензия ограничена
      проектами Orange. Решение по использованию за Алексеем.
- [ ] Шрифты лежат в `.otf` (~1,5 МБ на три реза). Конвертация в `.woff2`
      уменьшит вчетверо — правка одной строки в `@font-face`, инструмента
      для конвертации на машине нет.
- [ ] Уголковый орнамент на рекомендованной карточке (фирменная лента) не
      воспроизводился — приблизительная копия выглядела бы хуже отсутствия.

## Как проверялось

Прогон всех экранов в обеих темах в браузере: IDLE с зацикленной заставкой, выбор
аватара, разговор, три карусели, витрина стоек с переключением всех трёх моделей,
проверка адреса, GDPR-поток с цифровой клавиатурой, переход к продавцу, оценка,
dev-панель, оверлей обрыва связи на каждом экране. Вертикальные раскладки сверены
замерами: пересечений блоков нет, всё укладывается в 1920, полосы аватара держат
ровно 16:9, карточки тарифов и стоек не переполняются.

Виджет проверен на `localhost:8123`: в `IDLE` его скрипт не грузится, после
выбора «Muž» элемент создаётся с нужными атрибутами, автостарт нажимает кнопку
сессии, видео растягивается на всю зону, оверлей обрыва ложится поверх виджета,
возврат в `IDLE` удаляет элемент и не поднимает его обратно. Маршруты всех шести
инструментов прогнаны синтетическими событиями `anam-agent:tool-call-started` —
экраны и выбранная стойка совпадают; реплика из `message-received` уходит в титры.
Живой сессии пока не было: персона отвечает `Origin not allowed`, домен ещё не
внесён в кабинете.

Ошибок в консоли нет, кроме этого отказа. В сетевой панели только локальные
файлы и обращения к `api.anam.ai`.

Оговорка про замеры: панель предпросмотра временами переставала выдавать кадры, и
тогда CSS-переходы застывали на стартовом значении — `offsetWidth` показывал
устаревший размер при верных инлайн-стилях. Финальные цифры сняты после
принудительной отрисовки и совпадают со скриншотами.
