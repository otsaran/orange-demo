# Digital Assistant Demo

Одностраничный киоск-демо (портрет 1080 × 1920) с живым аватаром anam.ai. Без
сборки, без фреймворков, без внешних трекеров. Страница не для публичного
индексирования: `noindex`, показ по прямой ссылке.

Этот файл — точка сохранения проекта: состояние, принятые решения и что осталось.

## Запуск

```bash
python3 -m http.server 8123
```

Открыть `http://localhost:8123`. Двойной клик по `index.html` тоже работает, но при
`file://` браузер блокирует загрузку iframe с 3D-стойками, не идёт heartbeat и не
даёт микрофон (не защищённый контекст) — то есть аватар не запустится. Для показа — F11.

## Где развёрнуто

`main` на GitHub (`otsaran/orange-demo`) → Vercel → **https://humion.space**.
Пуш в `main` раскатывается сам, отдельной сборки нет: файлы отдаются как есть.

Домен должен быть в списке разрешённых origin у персоны в кабинете anam.ai —
иначе `POST /v1/auth/widget` вернёт `403 Origin not allowed` и аватар не
поднимется. Вписывается **полный origin со схемой**: `https://humion.space`.
Для локальной проверки туда же нужен `http://localhost:8123`.

Холст масштабируется под окно: `scale = min(w/1080, h/1920)`, поля чёрные,
вёрстка внутри фиксированная в px.

## Экраны и переходы

```
IDLE ──(касание)──► GENDER_SELECT ──► CONVERSATION
                                          │
        ┌──────────────┬──────────────────┼────────────────┐
        ▼              ▼                  ▼                ▼
      PLANS        DEVICE_3D        COVERAGE_CHECK       SELLER
        │              │                  │                │
        └──► COVERAGE_CHECK / LEAD_CAPTURE ┴────► CONVERSATION
                                          │
             ┌────────────────────────────┴────────────────┐
             │ «Ukončiť» или end_conversation              │ бездействие 45 с
             ▼                                             ▼
        FEEDBACK ──(оценка / крестик / 15 с)──►          IDLE
```

Бездействие `idleTimeoutSec` (45 с) уводит **сразу в `IDLE`**. Оценку киоск
по таймеру не спрашивает.

**Входов в `FEEDBACK` два, и оба — осознанное завершение:** инструмент
`end_conversation` (аватар решил, что разговор окончен) и кнопка «Ukončiť».
Раньше третьим входом был тот самый таймер, и оценка выскакивала посреди
разговора.

**Отсчёт бездействия сбрасывают не только касания.** Слушаются `pointerdown`,
`keydown`, `wheel` — и, отдельно, реплики разговора: событие `message-received`
приходит и на речь посетителя (роль `user`). Без этого разговор, который ведут
только голосом, обрывался через 45 секунд — браузер о речи ничего не знает, а
экрана никто не касался. Реплики намеренно не продлевают саму модалку оценки
(`noteConversationActivity` молчит в состоянии `FEEDBACK`): аватар под ней
продолжает говорить, и окно иначе не закрылось бы никогда.

Убирать таймер целиком нельзя: без него брошенный киоск остался бы с живой
сессией — звук в пустом зале, расход кредитов и чужой разговор для следующего
посетителя.

**FEEDBACK — окно, а не экран.** Раньше это была сплошная чёрная плоскость во
весь холст: она возникала поверх разговора (в том числе посреди фразы аватара)
и не давала вернуться — только оценить или ждать. Теперь карточка 820 px по
центру, полупрозрачное стекло с размытием, вокруг затемнение 50 %. Нижний экран
остаётся активным и виден насквозь, аватар не переезжает и договаривает начатое.

Три выхода: крестик, палец вверх, палец вниз. Крестик возвращает ровно туда,
откуда окно пришло, и заново запускает отсчёт бездействия; сессия аватара при
этом не рвётся. После оценки крестик прячется — уход в `IDLE` уже назначен.
Автовозврат по `feedbackTimeoutSec` сохранён намеренно: без него киоск после
ухода посетителя остался бы с живой сессией — звук в зале, расход кредитов и
чужой разговор для следующего.

Работает это потому, что `.screen` скрывается через `visibility`, а не
`display`: два экрана могут быть активны одновременно. Крестик обходится без
`go()` — тот заново выполнил бы `onEnter` нижнего экрана, и витрина стоек
перескочила бы на первую модель.

**Четыре плитки в CONVERSATION** (ключ = `data-quick`):

| Плитка | Куда ведёт |
|---|---|
| `mobile` — Paušály | карусель `plans.mobile` → `LEAD_CAPTURE` |
| `phones` — Telefóny | `DEVICE_3D` (витрина стоек) |
| `tv` — Televízia | карусель `plans.tv` → `COVERAGE_CHECK` |
| `internet` — Internet | карусель `plans.internet` → `COVERAGE_CHECK` |

Маршруты: если ключ плитки есть в `CONFIG.plans` — открывается карусель, иначе
берётся `QUICK_TARGET` в `app.js`. Новый раздел = блок в конфиге + плитка в HTML.

**PLANS** — один экран на все разделы. Заголовок, надпись на кнопке и её маршрут
(`next`) приходят из конфига. Карточка: название, крупный акцентный показатель,
подстрока, описание, старая/новая цена, срок, «Vybrať», список бенефитов.
Прокрутка пальцем со snap, перетаскивание мышью (для показа с ноутбука),
полоса-индикатор вместо системного скроллбара.

## Заставка IDLE

Вместо живого аватара в простое крутится зацикленная подборка, чтобы движок
аватара не работал вхолостую:

```
bg.webp 5 с → video_m ×4 → bg.webp 5 с → video_w ×4 → по кругу
```

**Видео считаются проходами, а не секундами.** Раньше стояло окно 20 000 мс, но
клип длится 5,084 с — это 3,93 прохода, и четвёртый обрывался на 93 %, посреди
движения. На экране это выглядело как подвисание: кадр замирал на середине петли
и скачком сменялся. Четыре полных прохода занимают почти столько же (20,4 с), но
склейка попадает туда, где последний кадр совпадает с первым.

Поэтому у `<video>` снят атрибут `loop` — проходы считает сам цикл по событию
`ended`. На случай, если воспроизведение не начнётся или `ended` не придёт
(заблокированный автоплей, ошибка декодирования), заведена страховка по времени:
без неё заставка замерла бы на одном клипе навсегда.

Видео без звука. Цикл живёт только в `IDLE`: при уходе на другой экран
`stubOn` снимается, обработчики `ended` отвязываются и видео ставятся на паузу.
Правится в `STUB_CYCLE` в `app.js` — поле `plays` у роликов, `ms` у картинок.

## Выбор аватара

Плитки квадратные, с зацикленными видео `orange_w.webm` / `orange_m.webm` во всю
площадь; подписи «Žena» / «Muž» вынесены под плитки. Выбранная отмечается
оранжевой рамкой с внутренним кольцом и оранжевой подписью — заливка не годится,
её перекрывает видео. У кнопок `aria-label`, потому что подпись снаружи.

Видео без звука, играют только на этом экране: при уходе ставятся на паузу, при
возврате перематываются на начало (`setGenderVideos` в `app.js`). Прежние
`orange_w.webp` / `orange_m.webp` остались как `poster` — они видны, пока видео
не декодировалось, иначе на их месте была бы чёрная плашка.

## Витрина стоек (DEVICE_3D)

Три готовые страницы `totem-1/2/3.html` вставляются в один iframe, у которого при
выборе карточки меняется `src`. Напрямую в разметку их вставить нельзя: у каждой
свои скрипты и совпадающие `id`. Один iframe вместо трёх — один живой WebGL-контекст.

Внутри страниц вёрстка переделана под киоск: модель во всю ширину (968 × 778),
кнопки `Rozmery` / `Pôvodný pohľad` / `Fotografia` перенесены из вертикальной
колонки справа под модель и приведены к форме киоскового `.btn-soft` (32 px,
высота 110, активная — оранжевая с чёрным текстом). Собственная карточка страницы
(фон, рамка, скругление, паддинг) убрана, фон `body` прозрачный — рамку даёт
киоск. Свой медиазапрос `max-width:640px` внутри оставлен: он не срабатывает
(iframe всегда 968 px), но нужен, если открывать файл напрямую.

Прежний пайплайн на `model-viewer` + `.glb` удалён целиком вместе с CSS-заглушкой
вращающегося куба.

## Аватар на внутренних экранах

| Экран | Зона аватара |
|---|---|
| `IDLE` | 1080 × 1180 |
| `CONVERSATION` | 1080 × 920 |
| `DEVICE_3D` | 800 × 450 (16:9) |
| `PLANS` | 800 × 450 (16:9) |
| `COVERAGE_CHECK` | нет аватара |

Полоса на внутренних экранах держит 16:9 и стоит по центру, а не растягивается на
всю ширину. Размер 800 × 450 упирается в карусель тарифов: карточкам нужно 1006 px
из 1010, поэтому больший аватар пришлось бы вычитать прямо из них. 800 × 450 —
потолок при нетронутых карточках, и он же взят на витрине стоек ради единообразия.

На `COVERAGE_CHECK` аватара нет вовсе: там будет обычная форма ввода адреса.
Следствие — оверлей обрыва связи на этом экране не показывается, он живёт внутри
слоя аватара (так же ведёт себя `GENDER_SELECT`).

## Виджет anam.ai

Аватар — веб-компонент `<anam-agent>` (`vendor/anam-agent.js`, версия 0.5.0),
а не iframe. Элемент создаётся в `#avatarWidget` после выбора пола и при уходе
в `IDLE` удаляется целиком — это единственная надёжная гарантия тишины в простое.
Скрипт виджета грузится лениво, при первом создании: в `IDLE` наружу не уходит
ни один запрос. Если файла во `vendor/` нет, подхватывается `scriptFallback` с CDN.

Ветка по `engine` в `loadAvatar`: `anam` + непустой `agentId` → виджет; иначе
непустой `url` → прежний iframe (pixel streaming); иначе — заставка-заглушка.
Оба аватара теперь в первой ветке: у женского с 2026-08-04 свой `agent-id`.

Четыре поправки к виджету, каждая по своей причине:

- **Автостарт.** Виджет ждёт нажатия собственной кнопки. На киоске её нажимаем
  сами (`.anam-cta-pill` в открытом shadow DOM) — выбор пола и есть то
  пользовательское действие, после которого браузер разрешает спросить микрофон.
- **Размер.** Виджет держит 16:9 и оставил бы в зоне аватара пустую полосу.
  В shadow DOM дописан стиль: `.anam-widget/.anam-sheet/.anam-video-region`
  тянутся на всю зону, кадрирование делает сам виджет (`object-fit: cover`).
- **Слои.** Внутри у виджета `z-index: 9999`, поэтому он перекрывал оверлей
  обрыва связи. `#avatarWidget` получил свой `z-index`, и внутренние слои
  остались заперты в нём.
- **Свой крестик.** Кнопка × «End call» завершала сессию и оставляла пустую
  зону — скрыта, разговор заканчивает только кнопка «Ukončiť» киоска.

Из хрома виджета выключены лента разговора (`ui-transcript`), субтитры
(`ui-captions`) и кнопка микрофона (`ui-mute-button`) — всё это у киоска своё.
Текстовое поле включено, но скрыто стилем: оно нужно как канал для вопросов от
кнопок (см. ниже). Водяной знак «Anam» остаётся — он снимается на
стороне сервиса, не в разметке.

**События.** `session-started` снимает оверлей обрыва и включает признак живой
сессии, `session-ended` его гасит, `error` показывает оверлей (вместе с
таймаутом `iframeLoadTimeoutMs`), `message-received` с ролью не-`user` уходит
в титры киоска. Heartbeat у виджета своей URL нет, поэтому пингуется
`anam.probeUrl` (`api.anam.ai`).

**Грабли, на которые уже наступили:** `session-started` включает признак живой
сессии, а тот раньше трактовался как «связь восстановилась» и вызывал
перезагрузку аватара — виджет монтировался заново, начинал новую сессию, и так
по кругу, сжигая кредиты. Перезагрузка теперь не срабатывает при живой сессии,
а `mount()` отбрасывает параллельные вызовы.

**Инструменты аватара** (client tools). Таблица `AVATAR_TOOLS` в `app.js` — весь
список того, что аватар может сделать с экраном; названия должны совпасть с
инструментами персоны в кабинете anam.ai:

| Инструмент | Аргументы | Действие |
|---|---|---|
| `show_section` | `section`: `mobile` \| `phones` \| `tv` \| `internet` | та же плитка, что и пальцем |
| `show_devices` | `model`: `totem1…3` | витрина стоек с нужной моделью |
| `check_coverage` | — | проверка адреса |
| `capture_lead` | — | форма для перезвона |
| `call_seller` | — | экран продавца |
| `end_conversation` | — | оценка и возврат в `IDLE` |

Серверные (webhook) вызовы игнорируются — их выполняет движок anam.ai сам.
Неизвестное имя инструмента только пишется в консоль.

Инструменты заводятся не руками, а скриптом `scripts/anam-tools.mjs` — в нём
те же шесть определений с описаниями и JSON-схемами:

```bash
ANAM_API_KEY=… node scripts/anam-tools.mjs --dry-run   # показать план
ANAM_API_KEY=… node scripts/anam-tools.mjs             # применить
```

Заведены и привязаны к обеим персонам 2026-08-04: инструменты общие на аккаунт,
персоне достаётся ссылка на них. Публиковать персону заново не нужно — виджет
берёт актуальный конфиг, а не снимок `publishedAt`.

`ANAM_PERSONA_ID` — это тот же UUID, что и `agent-id` в `config.js`; отдельного
идентификатора персоны у anam нет. Проверять привязку надо по полю `tools`
в ответе `GET /v1/personas/{id}`, а не по `toolIds`: второе приходит `null`,
даже когда инструменты на месте.

Скрипт идемпотентный: инструмент с таким же именем не дублируется, у него
обновляются описание и схема. `toolIds` персоны **дополняются**, а не
переписываются — системные `end_call`, `change_language`, `skip_turn` остаются
на месте. Ключ берётся из окружения и никуда не пишется; `.env.local` в
`.gitignore`. Персона задаётся через `ANAM_PERSONA_ID`, по умолчанию — мужская.

**Промпт персоны** — `scripts/persona-prompt.md`, заливается вторым скриптом:

```bash
ANAM_API_KEY=… node scripts/anam-persona.mjs --dry-run
ANAM_API_KEY=… node scripts/anam-persona.mjs
```

Он же ставит `languageCode: sk`, приветствие и настройки голоса. Прогнан на
обеих персонах 2026-08-04: язык, приветствие и промпт у них совпадают дословно.

**Настройки голоса под скорость отклика** (рекомендация Anam для живого
retail-демо, 2026-08-05): `voiceGenerationOptions = { speed: 1.05, emotion:
'content' }`, выставлено обеим 2026-08-05. Это именно `voiceGenerationOptions`,
а не `directorNotes`: последние управляют игрой аватара, и `content` среди их
`presetStyle` (`happy, warm, playful, supportive, sad, angry, distressed`) нет.
Диапазоны Cartesia sonic-3: `speed` 0,6–1,5, `emotion` — `neutral | calm |
angry | content | sad | scared`.

Отдельно есть верхнеуровневое поле `voiceSpeed`. Оно не документировано,
диапазон не проверяется (API принимает и `-0.5`, и `5`), и у обеих персон
стоит `0` — значение по умолчанию. Трогать его не надо: множитель скорости
живёт в `voiceGenerationOptions.speed`.

Важно: при смене `voiceId` эти настройки на стороне Anam сбрасываются —
после замены голоса скрипт надо прогнать заново.

**Кто чем владеет.** Скрипт перезаписывает только то, что лежит в репозитории
файлом: `systemPrompt` (из `persona-prompt.md`) и `initialMessage` (константа
`GREETING` — единственный источник приветствия). Язык, голос и его настройки
принадлежат кабинету — их подбирают на слух, и прогон скрипта не должен
возвращать их назад.

Расхождение по ним печатается всегда, но как справка:

```
· languageCode je 'uk', v skripte 'sk' – nechávam tak (--language prepíše)
```

Продавить их можно явными флагами `--language` и `--voice`. Наизусть слать
`VOICE` нельзя: `emotion` и диапазон `speed` 0,6–1,5 — это Cartesia, а у
ElevenLabs свои поля (`stability`, `similarityBoost`, `speed` 0,7–1,2) и
`emotion` там нет вовсе.

Правило появилось не на пустом месте: 2026-08-07 мужскую персону перевели в
кабинете на украинский (`languageCode: uk`, голос Artem Klopotenko, ElevenLabs
`eleven_flash_v2_5`; `voiceGenerationOptions` при смене голоса обнулились сами),
и обычный прогон скрипта это молча откатил бы.

**Промпт правится в двух местах, и кабинет главнее.** Блок `# STYLE CUES`
(теги настроения `[happy]`, `[curious]`, смех, оговорки «um») дописан в
кабинете anam уже после первого прогона скрипта — в файле его не было, и
повторный запуск стёр бы его молча. Файл подтянут из живой персоны, теперь
`--dry-run` не показывает `systemPrompt` в изменениях. Перед каждым запуском
скрипта стоит сверяться с живым промптом, иначе правки из кабинета теряются.

**Язык ответа задаёт промпт, а не `languageCode`.** Три ручки независимы:
`languageCode` — что аватар **слышит** (распознавание речи); системный промпт —
на чём **отвечает**; выбранный голос — как **звучит**. Их надо сводить вручную.

Раньше секция `# LANGUAGE` разрешала ровно два языка — словацкий и английский.
Из-за этого персона с `languageCode: uk` посетителя по-украински прекрасно
слышала, но упорно отвечала по-словацки или по-английски. С 2026-08-07 секция
открытая: начинать по-словацки, а дальше идти за посетителем на любой язык, с
вызовом `change_language`, чтобы распознавание переключилось следом. Под новый
язык промпт больше править не нужно — нужен только подходящий голос: привязанный
к одному языку (как украинский `Artem Klopotenko`) в остальных даст акцент.

**Сводка по предложениям (`# THE OFFER`) не пишется руками — она собирается из
`config.js`** при каждом прогоне скрипта и подставляется на место метки
`<!-- OFFER -->` в `persona-prompt.md`. Написанная руками, она разошлась бы с
карточками при первой же правке цен, и аватар утверждал бы одно, пока на экране
другое.

В сводку идут все тарифы, интернет, ТВ-пакеты и три размера стоек: `headline`,
`sub`, `note`, `benefits`, `commitment`. **Цены не идут** — они на экране, и
зачитывать их вслух аватару запрещено; суммы скидок внутри `note` идут, они
часть описания.

До этого модель знала только то, что киоск присылал в момент нажатия. На вопрос
голосом «чем L отличается от XL», заданный без касания экрана, ответить было
нечем — отсюда и жалобы на пустые ответы.

Цена решения — длина: промпт вырос с 5090 до 9092 знаков, а это время до первого
слова. Если на показе задержка окажется заметной, сводку стоит перенести в базу
знаний Anam (но её вызовы добавляют свою задержку) либо сократить до одной
строки на тариф.

**Словарь терминов** (`# SLOVAK WORDING`, добавлен 2026-08-07). Инструкции в
промпте английские — модель их исполняет, а не произносит, и дублировать их
по-словацки не надо: это удвоило бы длину, то есть задержку, и создало бы два
текста, которые разойдутся. По-словацки записано только то, что должно
прозвучать дословно: `paušál`, `balík`, `optika`, `viazanosť`, `stojan`,
`dostupnosť na adrese`, `predajca`. Без этого модель переводила с английского
на лету и придумывала синонимы, не совпадающие с надписями на плитках. Словарь
действует только пока аватар говорит по-словацки — иначе он тащил бы словацкие
термины в ответы на других языках.

Что заложено в текст: аватар —
цифровой презентёр Humion, оператор не называется ни разу (NDA), словацкий по
умолчанию с переходом на английский по просьбе (через системный
`change_language`), цены голосом не зачитываются — они на экране, выдумывать
числа запрещено, при сомнении — `call_seller`. Инструмент вызывается **до**
рассказа, чтобы посетитель видел то, о чём речь. Персональные данные не
спрашиваются: номер вводит сам посетитель после `capture_lead`.

**Приветствие теперь в одном месте — у персоны.** `GREETING` в
`scripts/anam-persona.mjs`:

```
Dobrý deň. Som digitálny prezentér Humion. S čím Vám môžem pomôcť?
```

Своего приветствия у киоска больше нет. `LINES.hello` удалён: он печатался в
титры сразу при входе в разговор, тогда как сессия поднимается ещё несколько
секунд — текст висел на экране задолго до того, как раздавался голос. Титры
теперь пишет только сам аватар, по `message-received`, поэтому слово и звук
приходят вместе, а полоса титров до этого просто пуста.

Заодно исчезло требование «два текста обязаны совпадать дословно» — оно и было
причиной двух приветствий подряд. `subtitles.say()` всё же отбрасывает повтор
той же строки: подстраховка на случай, если виджет пришлёт реплику дважды.

Длинную версию с перечислением разделов убрали намеренно: она занимала в титрах
ровно четыре строки, то есть всё поле без запаса, а разделы и так подписаны на
плитках. Короткое приветствие вдобавок раньше начинает звучать — это совпадает
с рекомендацией Anam по задержке.

**Обратное направление — киоск говорит аватару.** У виджета нет публичного
`talk()`, поэтому вопрос уходит через его же поле ввода — оно включено
(`ui-text-input: 'true'`), но скрыто стилем: на киоске не печатают, поле нужно
только как канал. Выключается одним флагом `anam.textBridge`.

| Что нажали | Что уходит аватару |
|---|---|
| плитка раздела | `anam.ask[ключ]` |
| «Vybrať» на карточке | шаблон `anam.askPlan` с фактами карточки |

Когда экран переключает **сам аватар** своим инструментом, не уходит ничего:
`openQuick(k, false)` молчит, титры остаются за ним.

**Впрыски помечены `[KIOSK]` и написаны по-английски.** Канала «системное
сообщение» у виджета нет, текст идёт как реплика посетителя — и раньше это
ломало язык: словацкие фразы вроде «Povedz mi o paušáloch» модель читала как
«посетитель заговорил по-словацки». Разговор на украинском срывался обратно на
словацкий при каждом касании экрана. Теперь в промпте есть правило: сообщения
с `[KIOSK]` — события экрана, не речь, язык из-за них не меняется и вслух они
не зачитываются.

**Шаблон даёт факты, а не сценарий.** Прежняя версия предписывала форму ответа
(«скажи в двух предложениях и спроси, что дальше»), модель исполняла её буквально
и звучала как заученный текст. Плюс в неё уходило три поля карточки из восьми —
рассказать было попросту нечего. Сейчас идут `headline`, `sub`, `note`,
`benefits`, `commitment`; цена не идёт намеренно — она у посетителя на экране,
и выдумать её модель не может.

Важная тонкость: виджет на preact, и состояние поля обновляется в следующем
такте — отправлять надо через `setTimeout`, иначе уходит пустая строка и
ошибки не видно. Если понадобится детерминированная речь по кнопке (зачитать
цену слово в слово), это повод перейти с виджета на JS SDK, где `talk()` есть.

## Оформление

Токены из дизайн-системы Orange (тёмный режим), сверены по Boosted 5.3 — их
собственной реализации гайда. Размеры и кегли не оттуда: они киоскные, под
просмотр стоя с полутора метров (текст от 32 px, тап-зоны от 120 px).

| | Значение | Откуда |
|---|---|---|
| Оранжевый | `#FF7900` | акцент тёмного режима (на белом у них `#F16E00`) |
| Текст на оранжевом | `#000` | правило контраста Orange |
| Фон / панель / линия | `#141414` / `#333` / `#666` | серые тона системы |
| Радиусы | 12 / 14 / 16 px | их 6–16 px, масштабировано под кнопку 130 px |
| Рамки | 2 px | `--bs-border-width: 0.125rem` |
| Нажатие | инверсия цветов | `.btn-primary:active` → чёрный фон, белая рамка |
| Неактивное | сплошной серый `#666` | у них `opacity: 1`, не прозрачность |
| Шрифт | Helvetica Neue 400/500/700 | `HelvNeueOrange` в их стеке |
| Фокус | 3 px кольцо + 2 px внутренний лем | правило доступности Orange |

Ни градиентов, ни теней, ни свечения — система плоская. Веса только 400/500/700:
`font-synthesis: none`, промежуточных начертаний в поставке нет.

**Чёрная тема** (переключатель в dev-панели, требование ТЗ): акцент `#000` на
тёмном фоне сливается, поэтому активные элементы белые с чёрным текстом — это
совпадает с их же `.btn-secondary` в тёмном режиме. Выбор состояния, который в
оранжевой теме показан обводкой, в чёрной дополнительно подсвечивается плашкой.

**Логотип** рисуется кодом: фирменный квадрат 96 × 96, слово в левом нижнем углу,
™ приподнято. Пропорции сняты с оригинала (слово ≈ 78 % ширины, поля 7–8 %).
В чёрной теме — монохромная инверсия.

**Плашка «Rozprávate sa s digitálnym asistentom (AI)»** — только текст с точкой,
без рамки и подложки; выровнена по правому отступу шапки.

**Титры** — полоса 968 × 230 при кегле 46 и строке 57 px, то есть ровно четыре
строки. `-webkit-line-clamp` стоял на 3 и молча срезал четвёртую: приветствие
персоны как раз занимало четыре и теряло конец. Теперь кламп 4 — совпадает с
высотой полосы.

## Замок на доступ

Демо закрыто шестизначным кодом. Реализовано в `middleware.js` — Vercel Routing
Middleware, выполняется до CDN и на **каждом** пути. Без валидной печати наружу
не отдаётся ни `index.html`, ни `app.js`, ни `config.js`, ни видео: посетитель
без кода видит только цифровую клавиатуру.

**Почему не проверка в браузере.** Демо статическое, файлы лежат на CDN и
тянутся по прямой ссылке. Проверка на JS пустила бы ко всему любого, кто
откроет `view-source:`, а сам код лежал бы в том же скрипте. Под NDA это не
защита, а её видимость.

**Почему не встроенный Password Protection Vercel.** Для продакшн-домена он
входит в Advanced Deployment Protection: Enterprise либо надстройка $150/мес
к Pro, с минимальным сроком 30 дней.

Две печати, каждая со своим сроком:

| Печать | Что открывает | Срок | Зачем такой |
|---|---|---|---|
| `k_doc` | одно открытие страницы | 20 с | из-за него перезагрузка снова просит код |
| `k_ast` | файлы: скрипты, стили, видео, шрифты | 12 ч | иначе на середине показа перестанут догружаться |

Обе подписаны HMAC-SHA256, подделать без `SECRET` нельзя. Страница от файла
отличается заголовком `Sec-Fetch-Dest`; страницы стоек идут в `<iframe>`
(`dest: iframe`) и потому считаются файлами — иначе они через 20 с требовали бы
код. Запрос без печати получает 404, а не 403: существование файла не
подтверждается.

**Код и ключ лежат прямо в `middleware.js`** — по решению заказчика, чтобы
ничего не заводить в кабинете Vercel. Цена: кто видит репозиторий, видит и код,
и он останется в истории git навсегда. Перенос в переменную окружения — правка
одной строки (`process.env.KIOSK_PIN`).

Чего этот замок **не** делает: не ограничивает число попыток. Шесть цифр — это
миллион комбинаций, и кроме задержки 600 мс на неверный ввод перебору ничто не
мешает. Для полноценного ограничения нужно хранилище (Vercel KV) — если демо
будет висеть в интернете долго, это стоит добавить.

## Приватность и NDA

- Камера не запрашивается нигде и никогда.
- **Микрофон уходит наружу** — иначе с аватаром не поговорить. Голос посетителя
  идёт по WebRTC в anam.ai, там распознаётся и попадает в LLM; расшифровка
  возвращается событием `message-received` и рисуется в титрах. Локально
  (Web Audio API) считается только уровень громкости для индикатора — вот он
  никуда не передаётся. Запись на стороне anam регулируется флагом
  `zeroDataRetention` у персоны — проверено 2026-08-04, стоит `false`.
  Если для показа нужно «ничего не хранить», флаг ставится тем же
  `PUT /v1/personas/{id}`.
- Номер телефона не сохраняется ни в `localStorage`, ни где-либо ещё; после
  отправки переменная очищается. В консоль пишется только `lead created`.
- `submitLead(phone)` в `app.js` — заглушка интеграции; в проде туда идёт
  зашифрованный ключ и запись в папку `Leady z avatara` (CB24).
- В `localStorage` только тема и обезличенные счётчики сессий и оценок.
- `noindex, nofollow` в head.
- Единственный внешний обмен — сессия anam.ai (голос посетителя и видеопоток
  аватара) и только между выбором аватара и возвратом в `IDLE`. В простое
  наружу не уходит ничего: элемент виджета удалён, скрипт лежит локально.

**Замены ради конфиденциальности** (каждая — одна строка в конфиге):
слово в логотипе → `logo`; названия партнёрских сервисов в бенефитах →
нейтральные («Prémiový filmový balík», «TV balík»). Имя оператора не звучит
и голосом: это отдельное правило в промпте персоны, а приветствие персоны
(`GREETING`) представляет её как «digitálny prezentér Humion».

Имя оператора долго оставалось написанным на экране в трёх местах, хотя
голосом уже не звучало — правило было про речь, а разметку не проверяли.
Убрано 2026-08-07:

| Где | Было | Стало |
|---|---|---|
| `IDLE_MESSAGES[0]` — крупный текст заставки | `…o službách Orange` | `…o našich službách` |
| `LINES.tv` — титры | `K Orange TV máte…` | `K našej televízii máte…` |
| GDPR-карточка в `index.html` | `predajcovi Orange` | `nášmu predajcovi` |

Проверка простая и её стоит гонять перед каждым показом:

```bash
grep -rn "Orange" app.js index.html config.js scripts/
```

Ничего не должно найтись. В `styles.css` и в имени репозитория название
остаётся — там его посетитель не видит.

## Контроль соединения

Три независимых источника: события `online`/`offline`, heartbeat каждые 5 с
(`no-store`, таймаут 3 с), таймаут загрузки аватара 15 с. Офлайн — после двух
неудач подряд, онлайн — после одной удачи (дребезг погашен).

**Подъём сессии — не обрыв.** Раньше `mount()` сразу ставил `iframeOk = false`,
и оверлей «Žiadne pripojenie k internetu» висел всё время нормальной загрузки —
секунды между выбором пола и первым кадром аватара. Таймаут 15 с задумывался
как сигнал отказа, но до него дело не доходило: посетитель уже читал, что
интернета нет. Введено отдельное состояние `connecting`: пока оно держится,
оверлей обрыва подавлен, показывается только крутящееся кольцо с надписью
`Spájam sa s asistentom…`. Обрыв объявляют лишь watchdog (`iframeLoadTimeoutMs`)
и событие `error` виджета — оба гасят `connecting`. Симуляция из dev-панели
(`forced`) сильнее и перебивает даже прелоадер.

Та же логика накрывает ветку с iframe (pixel streaming) — там `connecting`
снимает событие `load`.

**Вместо прелоадера — пустой зал.** Никакого кольца и никаких надписей: в зоне
аватара показывается `assets/bg.webp` под размытием — тот самый магазин, в
котором сняты видео аватара. Посетитель видит пустую комнату, в которую аватар
через секунду входит. Кольцо со словами «Spájam sa s asistentom…» читалось как
техническая заминка; пустой зал читается как часть сцены.

Размытие вынесено на `::before`, а не на сам `#avatarLoader`: `filter` на
элементе размыл бы и всё, что в него попадёт. Присвет −60 px и `scale(1.04)`
убирают мягкие края, иначе по бокам просвечивала бы подложка. В портретной
зоне кадр смещён на `50% 62%` — иначе от зала остаётся кусок стены.

`loaderDelayMs` теперь `0`. Отсрочка имела смысл при кольце, которое не должно
было мелькать; пустая комната наоборот должна быть на месте с первого кадра,
иначе на её месте сначала чернеет дыра.

**Уход — перекрёстное затухание, а не подмена.** Зал гаснет за 520 мс, виджет
за то же время проявляется: `#avatarWidget` вставляется прозрачным и получает
`is-live` на `session-started`. `display` анимировать нельзя, поэтому классов
два — `is-on` (вставлен) и `is-live` (виден). По той же причине слой зала
переключается классом, а не атрибутом `hidden`.

**Живая сессия аватара сильнее пробы.** Пока идёт WebRTC-поток (пришло
`session-started` и не было `session-ended`/`error`), оверлей не показывается,
даже если heartbeat не отвечает: работающий стрим — доказательство связи
надёжнее, чем opaque-fetch в `api.anam.ai`, который может резать расширение
или заголовок CORP. Без сессии (простой, iframe, заглушка) логика прежняя.
В dev-панели причина теперь разделена: строка **Relácia** (`dvíha sa…` /
идёт / последняя ошибка виджета) и строка **Sonda** (heartbeat и время
последнего ответа). Оверлей накрывает
только зону аватара, iframe под ним не выгружается и восстанавливается сам.
Текст переключается флагом `offlineMode`.

Heartbeat активен, когда известен внешний URL (`heartbeat.url` или адрес
аватара). Без него работают события браузера и таймаут iframe.

В узкой полосе 16:9 карточка оверлея идёт на ступень мельче (заголовок 38,
подпись 24, иконка 56), иначе текст не помещается и обрезается. Прелоадер
уменьшается там же и по тому же признаку `is-band` (кольцо 34, подпись 24).

## Dev-панель

Тройной тап в правый верхний угол холста (скрытая зона 190 × 190, интервал 1,6 с).
Панель полупрозрачная со стеклом (`backdrop-filter`), лежит поверх сцены.

- переключатель чёрной темы (тумблер, кружок красится в текущий акцент);
- «Simulovať výpadok internetu» — симуляция обрыва связи;
- «Reset do IDLE»;
- счётчики: состояние, пол, аватар, сессия аватара, соединение, heartbeat,
  сессии, лиды, оценки, FPS.

## Расхождения с SPEC.md — обсудить перед приёмкой

1. **§4.3, четыре кнопки.** В ТЗ: `Mobilné služby`, `Internet a TV`,
   `Ukáž mi zariadenia`, `Dostupnosť na mojej adrese`. Сейчас: `Paušály`,
   `Telefóny`, `Televízia`, `Internet` — по решению заказчика, чтобы совпадать
   с разделами сайта. Проверка адреса теперь внутри «Internet» и «Televízia».
2. **§10, пример CSS.** В ТЗ `--accent-contrast: #FFF` (белый текст на оранжевом).
   Поставлен `#000`: у Orange жёсткое правило контраста — текст на оранжевом
   чёрный. Переменная и её смысл сохранены.
3. **§4.3, высоты зон.** Подвал увеличен за счёт зоны аватара (920 вместо 1000),
   иначе кнопка продавца и индикатор микрофона не помещались с тап-зонами 120 px.
4. **IDLE.** Аватар не просто без звука — он не загружается вовсе. Ни чужой
   iframe, ни виджет нельзя заглушить снаружи, а требование «в простое без
   звука» жёсткое. Загружается после выбора аватара.
5. **Карусели тарифов** — новый экран, которого в ТЗ нет (§11 «не добавлять
   экранов»). Добавлен по прямому запросу заказчика.
6. **Витрина стоек вместо витрины устройств.** По ТЗ там телефоны и роутеры в
   `.glb`; по решению заказчика показываются собственные киоски трёх размеров
   готовыми Three.js-страницами.

## Как проверялось

Прогон всех экранов в обеих темах в браузере: IDLE с зацикленной заставкой, выбор
аватара, разговор, три карусели, витрина стоек с переключением всех трёх моделей,
проверка адреса, GDPR-поток с цифровой клавиатурой, переход к продавцу, оценка,
dev-панель, оверлей обрыва связи на каждом экране. Вертикальные раскладки сверены
замерами: пересечений блоков нет, всё укладывается в 1920, полосы аватара держат
ровно 16:9, карточки тарифов и стоек не переполняются.

**Виджет, локально.** В `IDLE` его скрипт не грузится; после выбора «Muž»
элемент создаётся с нужными атрибутами, автостарт нажимает кнопку сессии, видео
растягивается на всю зону, оверлей обрыва ложится поверх виджета, возврат в
`IDLE` удаляет элемент и не поднимает его обратно. Маршруты всех шести
инструментов прогнаны синтетическими событиями `anam-agent:tool-call-started` —
экраны и выбранная стойка совпадают.

**Живая сессия, https://humion.space, 2026-08-04.** Разговор идёт: видео
1152 × 768, поток один и тот же (перезапусков нет), оверлей снят, зона аватара
заполнена без полей. Реплики аватара уходят в титры киоска.

| Сказано аватару | Что он сделал |
|---|---|
| «Dobrý deň, čo mi viete ponúknuť k mobilu?» | `show_section {mobile}` → карусель тарифов, ответ по-словацки |
| «Can you switch to English and show me the large stand?» | `show_devices {totem3}` + системный `change_language {en}` → витрина, активна стойка 32–55″ |
| нажата «Vybrať» на «Paušál L» | вопрос с фактами карточки → две фразы про тариф и встречный вопрос, без единой цифры |

Ошибок в консоли нет. В сетевой панели только локальные файлы и обращения к
`api.anam.ai`.

Оговорка про замеры: панель предпросмотра временами переставала выдавать кадры, и
тогда CSS-переходы застывали на стартовом значении — `offsetWidth` показывал
устаревший размер при верных инлайн-стилях. Финальные цифры сняты после
принудительной отрисовки и совпадают со скриншотами.
